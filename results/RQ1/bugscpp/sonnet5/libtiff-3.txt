The bug: `horizSubSampling` was parsed from `optarg` with no validation, unlike `vertSubSampling` right below it which checks for valid values (1, 2, or 4). An arbitrary or malformed value (including 0 or negative) can propagate into subsampling calculations later, causing division-by-zero or out-of-bounds memory access. The fix mirrors the existing validation used for `vertSubSampling`.
