```c
uint32
TIFFNumberOfStrips(TIFF* tif)
{
	TIFFDirectory *td = &tif->tif_dir;
	uint32 nstrips;

    /* If the value was already computed and store in td_nstrips, then return it,
       since ChopUpSingleUncompressedStrip might have altered and resized the
       since the td_stripbytecount and td_stripoffset arrays to the new value
       after the initial affectation of td_nstrips = TIFFNumberOfStrips() in
       tif_dirread.c ~line 3612.
       See http://bugzilla.maptools.org/show_bug.cgi?id=2587 */
    if (td->td_nstrips != 0)
        return td->td_nstrips;

	nstrips = (td->td_rowsperstrip == (uint32) -1 ? 1 :
	     TIFFhowmany_32(td->td_imagelength, td->td_rowsperstrip));
	if (td->td_planarconfig == PLANARCONFIG_SEPARATE)
		nstrips = _TIFFMultiply32(tif, nstrips, (uint32)td->td_samplesperpixel,
		    "TIFFNumberOfStrips");
	return (nstrips);
}
```

The bug (per the comment that was already in the source, describing bugzilla #2587) is that the function always recomputes `nstrips` from `td_rowsperstrip`/`td_imagelength`, ignoring the case where `td_nstrips` was already set and later adjusted (e.g. by `ChopUpSingleUncompressedStrip`, which resizes `td_stripbytecount`/`td_stripoffset` but doesn't necessarily change `td_rowsperstrip`/`td_imagelength` in a way that recomputing would match). The fix adds an early return of the cached `td->td_nstrips` when it's already been computed (non-zero), so the function stays consistent with the actual size of the strip arrays.
